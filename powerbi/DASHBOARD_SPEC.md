# Power BI dashboard spec

Build this in **Power BI Desktop** (Windows). Everything it needs is generated by the pipeline; no
numbers are typed in by hand.

## 1. Generate the data

```bash
make powerbi          # or: uv run bev powerbi
```

This writes `powerbi/export/` (git-ignored, because it is derived from the licensed Dominick's data):

| File | Grain | Rows (approx.) |
|---|---|---|
| `fact_sales_weekly.parquet` | brand x pack x store x week, all brands | 2.4M |
| `fact_forecast.csv` | series x store x week x model (backtest) | 269k |
| `fact_promo_events.csv` | promoted store-week (backtest period) | 39k |
| `dim_product.csv` | series (brand x pack) | 103 |
| `dim_upc.csv` | UPC with brand / pack mapping | 1,746 |
| `dim_store.csv` | store with zone, price tier, demographics | 107 |
| `dim_calendar.csv` | Dominick's week with dates and holidays | 400 |
| `elasticities.csv`, `cross_elasticities.csv` | model outputs | 12 / 60 |
| `promo_roi.csv`, `price_optimization.csv`, `forecast_metrics.csv` | model outputs | small |
| `scenario_grid.csv` | scenario series x price change x affected series | 513 |

## 2. Load and model

1. **Get data -> Parquet** for `fact_sales_weekly.parquet`; **Text/CSV** for the rest.
2. In Power Query set types: `week`, `store` = Whole number; prices/units = Decimal; `week_start` = Date.
3. **Model view** relationships (single direction, many-to-one):

| From (many) | To (one) |
|---|---|
| `fact_sales_weekly[week]` | `dim_calendar[week]` |
| `fact_sales_weekly[store]` | `dim_store[store]` |
| `fact_sales_weekly[series]` | `dim_product[series]` |
| `fact_forecast[week]`, `[store]`, `[series]` | `dim_calendar`, `dim_store`, `dim_product` |
| `fact_promo_events[week]`, `[store]`, `[series]` | `dim_calendar`, `dim_store`, `dim_product` |
| `elasticities[series]` | `dim_product[series]` |
| `price_optimization[series]` | `dim_product[series]` |

   Leave `scenario_grid` and `cross_elasticities` **disconnected** (they are filtered by their own
   slicers).
4. Create a `_Measures` table and paste all measures from `powerbi/measures.dax`.
5. **Modeling -> New parameter -> Numeric range**: name `Price Change %`, min -20, max 20,
   increment 5, default 0 (used on page 5).
6. Theme: keep one colour per brand across every page (e.g. Coke blue, Diet Coke orange, Pepsi
   green, Diet Pepsi yellow, 7Up pink, Private Label dark green -- the same mapping as the charts in
   `results/figures/`). Use **data labels** on bars so colour is never the only cue.

## 3. Pages

### Page 1 -- Executive overview
- **KPI cards**: Revenue, Gross Margin, Gross Margin %, Equivalent Cases, Units YoY %, Promo Share of Units.
- **Line chart**: Revenue and Gross Margin by `dim_calendar[week_start]` (two separate small charts,
  never a dual axis).
- **Stacked column**: Equivalent Cases by `dim_calendar[year]`, legend `dim_product[brand]`
  (filter `in_model_scope = TRUE` or group the rest as Other).
- **Slicers** (one row at the top): year, price tier, pack.
- Caption: *"Soft drinks are a heavily promoted category: X% of units sell on promotion."*

### Page 2 -- Price & elasticity
- **Bar chart**: `elasticities[own_elasticity]` by `series`, sorted ascending, with error bars from
  `ci_low` / `ci_high` (Analytics pane -> Error bars).
- **Matrix heatmap**: rows `cross_elasticities[focal_brand]`, columns `[competitor_brand]`, values
  `Cross Elasticity`, conditional formatting **diverging** (red negative - grey 0 - blue positive);
  slicer on `[pack]`. Show blanks for `identified = FALSE` with a footnote "priced in lockstep".
- **Card**: Volume Impact of 10% Price Cut for the selected series.
- **Table**: `interpretation` text column.

### Page 3 -- Promotion performance
- **Clustered bars**: Promo Lift % and Promo ROI by `fact_promo_events[promo_label]`, split by pack.
- **Line**: Promo ROI by `depth_bucket` with a constant line at 1.0 ("break-even").
- **Table**: `promo_roi.csv` sorted by `roi` -- top 10 and bottom 10 (Top N filter).
- **KPI cards**: Discount Investment, Incremental Gross Margin, Net Margin Impact, Promo ROI.

### Page 4 -- Forecast accuracy
- **Slicer**: `fact_forecast[model]` (default lightgbm).
- **Line chart**: Actual Units (Backtest) vs Forecast Units by `week`, small multiples by `series`.
- **Bar chart**: WAPE LightGBM vs WAPE Seasonal Naive by `series`.
- **Clustered bars**: Forecast WAPE by `fact_forecast[promo]` (0 = non-promo, 1 = promo) and model.
- **Card**: WAPE Improvement vs Seasonal Naive %, Forecast Bias %.

### Page 5 -- Scenario planner
- **Slicer**: `Price Change %` parameter (slider) and `scenario_grid[scenario_series]` (single select).
- **Cards**: Scenario Volume Change %, Scenario Revenue Change, Scenario Gross Margin Change, with
  Scenario GM Low (P5) / High (P95) as the range.
- **Table**: `scenario_grid[series]`, `[role]`, Scenario Units, Scenario Gross Margin Change --
  shows the target brand and the volume it takes from competitors.
- **Text box (required)**: "Assumes constant elasticities, no competitor price reaction and fixed
  unit cost. Directional, not a forecast."
